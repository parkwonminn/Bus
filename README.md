# 통학버스 동선 계산기

유치원·학원 통학차량의 방문 순서를 카카오모빌리티 도로망 기준으로 계산하고,
좁은 골목 주행을 줄이도록 정류장 이동을 제안하는 도구입니다.

정적 페이지(GitHub Pages)와 REST 키를 보관하는 작은 프록시로 나뉩니다.
**REST 키는 프록시에만 두고 브라우저로 내려보내지 않습니다.**

```
index.html      화면 (GitHub Pages 에 올라가는 부분)
config.js       프록시 주소와 카카오 JavaScript 키
proxy/lib.mjs   카카오 API 호출 + 도로 등급 판정 (공용)
proxy/worker.js Cloudflare Workers 용
proxy/server.mjs 로컬 개발 · 자체 점검용
```

---

## 1. 카카오 키 발급

1. [카카오 개발자 콘솔](https://developers.kakao.com)에서 애플리케이션을 만듭니다.
2. **앱 키** 메뉴에서 두 가지를 받습니다.
   - `REST API 키` — 프록시에서 쓰며 **절대 공개 저장소에 넣지 마세요.**
   - `JavaScript 키` — 지도 표시용. 공개를 전제로 한 키입니다.
3. **플랫폼 > Web** 에 배포 주소를 등록합니다. 예: `https://<깃허브아이디>.github.io`
   (로컬 테스트용으로 `http://127.0.0.1:8777` 도 함께 등록해 두면 편합니다.)
4. 카카오모빌리티 **길찾기 API 사용 신청**을 하고 승인을 받습니다.
   승인 전에는 호출이 403으로 거부됩니다.

---

## 2. 프록시 확인 (로컬)

키가 제대로 동작하는지 먼저 확인합니다.

```powershell
$env:KAKAO_REST_KEY="발급받은_REST_키"
node proxy/server.mjs --selftest
```

주소 검색 → 거리 행렬 → 실제 경로까지 3단계를 실행하고 결과를 출력합니다.
여기서 실패하면 키 또는 API 사용 승인 문제입니다.

통과하면 서버를 띄웁니다.

```powershell
node proxy/server.mjs
```

`config.js` 의 `PROXY_URL` 을 `http://127.0.0.1:8788` 로 두고,
다른 터미널에서 정적 서버를 띄운 뒤 브라우저로 엽니다.

```powershell
python -m http.server 8777
```

## 3. 프록시 배포 (Cloudflare Workers)

GitHub Pages 는 정적 파일만 올라가므로 프록시는 따로 배포해야 합니다.
무료 한도로 충분합니다.

```bash
cd proxy
npx wrangler deploy
npx wrangler secret put KAKAO_REST_KEY      # 여기에 REST 키를 붙여 넣습니다
```

`wrangler.toml` 의 `ALLOW_ORIGIN` 을 본인 Pages 주소로 바꿉니다.

```toml
[vars]
ALLOW_ORIGIN = "https://<깃허브아이디>.github.io"
```

배포되면 `https://bus-route-proxy.<계정>.workers.dev` 주소가 나옵니다.

---

## 4. GitHub Pages 배포

`config.js` 를 채웁니다.

```js
window.APP_CONFIG = {
  PROXY_URL: 'https://bus-route-proxy.<계정>.workers.dev',
  KAKAO_JS_KEY: '발급받은_JavaScript_키'
};
```

저장소에 올리고 **Settings > Pages** 에서 배포 브랜치를 지정하면 끝입니다.
`proxy/` 폴더가 함께 올라가도 정적 페이지 동작에는 영향이 없습니다.

> 무료 플랜의 GitHub Pages 는 공개 저장소를 씁니다.
> **실제 원생 주소가 담긴 파일은 커밋하지 마세요.** 주소는 브라우저에서 입력받아
> 저장도 그 기기의 localStorage 에만 됩니다.

## 큰 길 우선은 어떻게 동작하나

1. **소요시간 기준 순서 결정** — 거리가 아니라 실제 주행시간으로 방문 순서를 정합니다.
   저속 골목이 낀 순서는 자연히 뒤로 밀립니다.
2. **도로 등급 판정** — 카카오가 돌려준 도로명으로 폭을 추정합니다.
   `~대로` → 간선, `~로` → 일반, `~길`·`~N번길` → 이면도로.
   이름이 없는 도로는 주행속도 20km/h 미만일 때만 골목으로 셉니다.
3. **정류장 이동 제안** — 이면도로에 선 정류장은 **이미 받아 온 경로 위에서**
   가장 가까운 큰 길 지점을 찾아 제안합니다. 추가 API 호출이 없습니다.
4. **U턴·고속도로 회피** — 카카오 길찾기의 `avoid` 옵션을 씁니다.

골목을 0%로 만들 수는 없습니다. 간선도로가 없는 주택가는 어떤 경로로도
이면도로를 지나야 합니다. 이 도구는 골목을 줄이고 남은 구간을 눈에 보이게 할 뿐이며,
실제 도로 폭과 회전 반경 판단은 기사님 몫입니다.

## 호출량 주의

한 번 계산할 때 드는 호출:

| 단계 | 호출 수 |
|---|---|
| 주소 → 좌표 | 좌표로 직접 입력하지 않은 주소 수만큼 |
| 거리·시간 행렬 | **지점 수만큼** (다중 목적지 API) |
| 실제 주행 경로 | 1회 (다중 경유지 API) |
| 순서 변경·정류장 이동 | 1회씩 (경로만 다시 받음) |

지점 10곳이면 한 번 계산에 약 11~21회입니다.
카카오모빌리티 길찾기 API 는 일일 한도가 있으니, 반복 계산이 잦으면
저장된 노선을 재사용하세요.

## 개인정보

- 입력한 주소·좌표는 본인이 운영하는 프록시를 거쳐 **카카오 API 로만** 전송됩니다.
- 저장·기록은 사용한 기기의 localStorage 에만 남고 서버로 가지 않습니다.
- 다만 **아동의 주소를 다루는 서비스**입니다. 보호자 동의, 접근 권한 관리,
  공용 PC 에서의 기록 삭제 같은 절차는 별도로 갖추셔야 합니다.
- GitHub Pages 는 누구나 접근 가능한 공개 주소입니다. 내부용으로만 쓰실 거라면
  Cloudflare Access 같은 접근 제한을 앞단에 두는 편이 안전합니다.
